# Домашнее задание к занятию "Домашнее задание к занятию «Terraform»" - Костенко Максим

## Задание

Установите Terraform на компьютерную систему (виртуальную или хостовую), используя лекцию или инструкцию. download: https://hashicorp-releases.yandexcloud.net/terraform/

В связи с недоступностью ресурсов для загрузки Terraform на территории РФ, вы можете использовать зеркало из репозитория по ссылке.

Повторите демо из лекции! документация провайдеров: https://library.tf/providers

**1. Обновление списка пакетов и установка зависимостей**
```bash
sudo apt-get update && sudo apt-get install -y wget unzip
```
Объяснение:
- apt-get update — обновляет локальный индекс пакетов, чтобы система знала о последних доступных версиях.
- apt-get install -y wget unzip — устанавливает утилиты:
- wget — для скачивания файлов по HTTP/HTTPS;
- unzip — для распаковки ZIP-архивов.

**2. Создание рабочей директории**
```bash
sudo mkdir -p /opt/terraform
sudo chown $USER:$USER /opt/terraform
cd /opt/terraform
```
Объяснение:
- sudo mkdir -p /opt/terraform — создаёт директорию /opt/terraform. Флаг -p создаёт все промежуточные директории и не выдаёт ошибку, если директория уже существует.
- sudo chown $USER:$USER /opt/terraform — меняет владельца директории на текущего пользователя, чтобы можно было работать с файлами без sudo. Переменная $USER автоматически подставляется в имя вашего пользователя.
- cd /opt/terraform — переходим в рабочую директорию.

**3. Скачивание Terraform с зеркала**
```bash
wget https://hashicorp-releases.yandexcloud.net/terraform/1.16.2/terraform_1.16.2_linux_amd64.zip
```
**4. Распаковка архива**
```bash
unzip terraform_1.16.2_linux_amd64.zip
```
**5. Перемещение бинарного файла в системную директорию**
```bash
sudo mv /opt/terraform/terraform /usr/local/bin/
```
Объяснение:
- /usr/local/bin — стандартная директория для пользовательских исполняемых файлов, которая уже включена в переменную окружения PATH.
- После перемещения команду terraform можно вызывать из любого места без указания полного пути.

Ожидаемый результат: Команда выполняется без вывода. Проверить можно командой which terraform — должен вернуться путь /usr/local/bin/terraform.

**6. Проверка установки**
```bash
terraform -version
```
**7. Настройка зеркала провайдеров**
```bash
nano /opt/terraform/.terraformrc
```
Содержимое файла /opt/terraform/.terraformrc:
```hcl
provider_installation {
  network_mirror {
    url     = "https://terraform-mirror.yandexcloud.net/"
    include = ["registry.terraform.io/*/*"]
  }
  direct {
    exclude = ["registry.terraform.io/*/*"]
  }
}
```
Пояснение конфигурации:
- Блок network_mirror указывает Terraform использовать зеркало Yandex Cloud для всех провайдеров из официального реестра registry.terraform.io.
- Блок direct с exclude запрещает прямое обращение к официальному реестру, что критично в условиях ограниченного доступа.
- Директива include = ["registry.terraform.io/*/*"] означает, что через зеркало загружаются все провайдеры (любой namespace и любой провайдер).

**8. Указание Terraform путь к файлу конфигурации**

Так как Terraform по умолчанию ищет .terraformrc в домашней директории (~/.terraformrc), нужно сообщить ему о новом расположении через переменную окружения TF_CLI_CONFIG_FILE.
```bash
echo 'export TF_CLI_CONFIG_FILE=/opt/terraform/.terraformrc' >> ~/.bashrc
source ~/.bashrc
```
Объяснение:
- TF_CLI_CONFIG_FILE — официальная переменная Terraform, задающая путь к файлу CLI-конфигурации.
- ~/.bashrc — добавляет строку в конец файла конфигурации bash, чтобы переменная устанавливалась автоматически при каждом входе в систему.
- source ~/.bashrc — применяет изменения в текущей сессии без перезахода.

Проверка:
```bash
echo $TF_CLI_CONFIG_FILE
```
Ожидаемый результат: /opt/terraform/.terraformrc

**9. Создание тестовой конфигурации**
```bash
mkdir -p /opt/terraform/demo && cd /opt/terraform/demo
nano main.tf
```
Содержимое main.tf:
```hcl
terraform {
  required_providers {
    random = {
      source  = "hashicorp/random"
      version = "~> 3.0"
    }
  }
}

resource "random_string" "example" {
  length  = 8
  special = false
}

output "result" {
  value = random_string.example.result
}
```
Объяснение:
- Блок terraform с required_providers объявляет зависимость от провайдера hashicorp/random версии 3.x.
- Ресурс random_string создаёт случайную строку длиной 8 символов без специальных знаков.
- Блок output выводит результат после применения конфигурации.
- Этот пример выбран потому, что провайдер random работает полностью внутри Terraform и не требует облачных учётных данных — идеально для проверки работоспособности.

**10. Инициализация проекта**
```bash
terraform init
```
Объяснение:
- Инициализирует рабочую директорию Terraform.
- Скачивает необходимые провайдеры (в данном случае hashicorp/random) через настроенное зеркало.
- Создаёт скрытую директорию .terraform и файл .terraform.lock.hcl с фиксацией версий провайдеров.

```bash

```
Объяснение:

Terraform анализирует конфигурацию и показывает, какие действия будут выполнены, без реального применения. В данном случае будет показано создание одного ресурса random_string.example.

**13. (Опционально) Удаление ресурсов**
```bash
terraform destroy
```
Объяснение:

Удаляет все ресурсы, созданные текущей конфигурацией. Для провайдера random это просто удаление записи из состояния, но команда полезна для очистки. Подтвердите вводом yes.
